Step 2 of 4 · Text extraction (OCR)

OCR reads every character — it doesn't understand any of it yet

The OCR engine scans the page and converts pixels into plain text, in reading order. At this point the system has no idea which word is a test name, which is a number, or which is a unit — it's just a wall of text.

Sunrise Diagnostics — Pathology Report
Patient: R. Sharma  Age/Sex: 34/M
Hemoglobin  13.8  g/dL  13.0-17.0
WBC Count  11,400  /uL  4,000-11,000
RBC Count  4.6  mill/uL  4.5-5.9
Platelet Count  1.4  lakh/uL  1.5-4.1
Hematocrit(PCV)  41.2  %  40-50

Notice: the raw text is just one line after another — no columns, no labels. That's the input to the next step.

Step 3 of 4 · Categorization (field mapping)

Now each piece of text is labeled with what it means

The system looks for patterns in the raw lines — a name, followed by a number, followed by a unit, followed by a range — and tags each piece as Test, Value, Unit or Reference range. Once a value is tagged, it can be checked against its range to see if it's Normal, High or Low.

Step 4 of 4 · Structured result

Both reports, fully tabulated and ready for QC

Every field extracted this way is scored with a confidence percentage. Anything below the review threshold is highlighted so a reviewer checks it before it's accepted — values can be corrected inline, and each report is signed off separately.

Choosing How To Build This

Two ways to read a report

The walkthrough above shows the mechanics. Underneath, there are two fundamentally different ways to build it.

Classical OCR + Table Engines

Tesseract · AWS Textract · Azure Document Intelligence · Google Document AI

Strong, purpose-built table & grid detection
Reads text first, understands it in a separate step
Predictable, deterministic — same input, same output
Needs rules or a language model on top for meaning

Direct Multimodal APIs

Gemini · GPT · Claude — one model, one call

Reads and understands the page in a single pass
Handles multi-report bundling on its own
Fastest to build — describe the JSON shape, done
Cost varies a lot by provider — see below

Our Take

Recommended approach

A layered strategy — right engine for the right job, humans as the safety net.

1

Paid OCR (Textract / Document Intelligence) for raw reading + table structure

Cheap, purpose-built, deterministic — this does the heavy lifting of reading tables accurately.

2

A cloud LLM call only for semantic field-name normalization

Used narrowly to resolve header/synonym variance ("Hb" vs "Hemoglobin") — not to re-read numeric values.

3

Human-in-the-loop review as the permanent safety net

Low-confidence fields are always confirmed by a reviewer before becoming canonical data — no full automation on day one.
